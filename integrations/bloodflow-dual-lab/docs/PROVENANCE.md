# 원본과 변경 이력

## 확보한 기준 자료

요청한 별도 파일명 `BLOODFLOW 5.1 Research Workbench`는 찾지 못했습니다. 보관된 `BLOODFLOW_5_2_Material3.html`을 확보했고 내부 코드가 `5.1-model-material3-ui`, 실험 기록이 `BLOODFLOW-5.1`로 표시된 것을 확인했습니다. 따라서 이 결과물은 **5.2 배포 파일에서 회수한 5.1 모형의 확장본**입니다. 정확한 독립 5.1 원본 전체와 동일한 파일이라고 주장하지 않습니다. 별도 5.1 원본과의 최종 대조는 원본 제공이 필요합니다.

`original/BLOODFLOW_5_2_Material3.html`은 변경 없이 보존했습니다. `original/SHA256.json`의 해시로 바이트 보존을 확인할 수 있습니다. 이 파일의 내장 `bloodflow-engine`에서 필요한 원래 코드를 추출했습니다.

## 실제로 확인한 원래 기능

| 영역 | 코드에서 확인한 구현 | 변경·확장 |
|---|---|---|
| 시간·사건 | 난수 생성기, 포아송 수, 우선순위 힙, World, 도착·복귀·만료 사건 | 동일 난수/포아송/힙과 운송·만료 기반 재사용 |
| 제제 | RBC 객체, 기한·검사 대기·ready·review·truck·terminal 상태 | RBC/PLT/FFP, ABO/RhD 공급 검사와 검사 2시간 가상 지연 |
| 수요·공급 | 일 단위 포아송 수요·입고, FIFO/FEFO, 자동 배차와 재배치 | 6시간 수요 슬롯, 조건부 로그정규 변동성, 입고·수요·혈액형 난수 분리 |
| 운송 | World의 dispatch/arrival/return, 직접 적재·하역·문·냉각 메서드 | 공통 운송 기반 재사용. 출고 실패 시 재고 유실 방지, 도착 기한 확인 |
| 온도 | 1차 열전달 가정, 온도 노출 누적, 검토 보류 | 신형 제제에는 명시적인 가상 온도 기록과 제제별 보류 규칙. 기존 열전달 코드는 원본 모듈에 보존 |
| 지리 | 기관 32개 내장, Leaflet, OSRM 행렬·경로 조회 코드 | 공식 주소를 대조한 기관 4개로 좁힘. 유향 경로 12개, OSM 도로 1,394개 저장 |
| 실험·출력 | seed를 지정한 반복·기준/실험군 계산, CSV·JSON 내보내기 | 짝지은 차이·표본 SD·t 구간, 분모 정의, 독립 작업자 계산 |
| 공유 서버 | 이 단일 HTML에서 WebSocket 권위 서버는 확인되지 않음 | 새 공통 서버, 역할 권한, 버전·이벤트·클라이언트 순번, 재연결·복원 |
| 생물 규칙 | 원래 RBC의 기본 만료는 생성 후 28일. 혈액형 필드가 있어도 take()에서 적합성을 검사하지 않음 | 선택한 문헌 기반 제품으로 기한 수정, 제제별 적합성 검증 |

`src/legacy-baseline.mjs`는 원래 함수와 World의 독립 검증용 추출본입니다. DOM wrapper와 지도 그리기 부수효과만 분리했습니다. `src/legacy-core.mjs`는 같은 코드에 새 제제의 관찰 함수를 연결하는 최소 hook을 추가한 것입니다. `DualWorld extends World`가 새 연구 규칙을 구현합니다. 원본 HTML 자체를 변경하지 않았습니다.

원래 UI의 전체 시각 표현·직접 차량 조작 UI·기관 32개 범위는 새 화면에서 모두 재현하지 않았습니다. 해당 원본과 메서드는 보존돼 있지만 새로운 관제 화면은 4개 기관과 자동 공급 정책을 중심으로 합니다. 기존 장비 성능·보관 용량·연속 열전달을 실제 기관의 운영 성능처럼 사용하지 않습니다.
