# 지도 원본·제공자 조사

조사 시각: 2026-10-22 UTC. 이 문서는 원본 정적 분석과 일회 HTTP 진단을 구분한다. 최종 수정본의 자동·브라우저 테스트는 별도 검증 보고서를 기준으로 한다.

## 입력 파일 대조

- 기준 HTML SHA-256: `f13e82c67b10530a566ac77bf5ae4b9bc930d6f66316bb7eb73ec13ae3f4a11c`.
- 전국 프로토타입 SHA-256: `8c115f5d5183a3f37c315a162ad4d814981397a5edd96ac9ee184d1106eb9166`.
- 프로토타입은 기준 파일의 기존 모듈을 바꾸지 않고, 마지막에 별도 스타일·버튼·고정 전체화면 패널·스크립트를 추가한다. `position:fixed;inset:0`인 `#bf-national-panel`을 기존 화면 위에 표시한다. 독립 경로와 공통 최상위 내비게이션은 없다.
- 전국 모형은 17개 지역 × (가상 허브 1 + 가상 수요 거점 5) = 102개라고 표시하지만, 계산은 17개 지역별 단일 재고 배열에서 수행한다. 102개의 개별 거점 재고·차량은 계산하지 않는다.
- 지도는 실제 경계선 없이 좌표 원·직선으로 그린 SVG다. 기준 인천 도로 캐시를 전국 경로로 사용하지 않는다.
- 전국 계산은 독립 `simulate(cfg,shared)` 함수다. 기존 `LabClient`, `DualWorld`, Biology Lab, 공통 WebSocket 상태, 자동 저장과 연결되지 않는다. 실행 중 주 스레드를 사용하며, 반복 몬테카를로 평균·표준편차·짝지은 신뢰구간을 계산하지 않는다.
- 기준/전국 정책의 수요 난수 사용 순서는 일정하지만, 시드 한 번의 두 결과만 비교한다. 공급량은 현재 재고에 의존하므로 정책에 따라 입고 총량도 달라질 수 있다. 결과의 분모와 가정이 이를 명확히 설명해야 한다.
- 제제 구분·ABO/RhD·온도 보류·검사 상태를 전국 계산에서 검토하지 않는다. 가상 사용기한 하나를 모든 재고에 적용한다. 기간 말 운송 중 물품과 잔여 재고를 결과에 포함한 보존 검증도 없다.
- 따라서 프로토타입의 전국 관찰·정책 비교 아이디어는 재사용하되, 계산·협업·페이지 구조를 기존 시스템에 통합해야 한다.

## 기준 버전의 요청 경로

기준 `src/app.mjs`는 서버 실행 때 `/bloodflow/data/facilities.json`, `routes.json`, `roads.geojson`을 읽는다. 단일 HTML은 내장 데이터를 사용한다. 런타임 OSRM 요청은 없으며 저장된 12개 방향별 경로를 사용한다.

온라인 배경은 사용자가 버튼을 누를 때만 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`를 요청한다. `file://`에서는 켜지 않고 안내만 보여준다. 따라서 파일 직접 실행에서 온라인 타일이 안 나오는 것은 해당 분기의 의도된 동작이다. 저장 도로는 보이지만 해안·행정경계가 없어 배경이 빈 것으로 느껴질 수 있다. `tileerror` 알림만 있고 상태별 처리·대기열 제한·지수 백오프·차단기는 없다.

기준 서비스워커는 같은 출처의 `/bloodflow/` 요청만 처리한다. 네트워크 실패와 캐시 부재가 겹치면 직접 `new Response('Offline',{status:503})`을 만든다. 이 **앱 내부 합성 503**은 OSM 타일 서버의 503과 다르다. 외부 타일·OSRM 요청은 이 서비스워커 범위에 들어오지 않는다. 네트워크 패널의 URL·응답 출처·본문 없이 둘을 동일시할 수 없다.

## 실제 진단 관찰과 한계

원본 사용자 환경의 HAR·콘솔·503 응답은 제공되지 않았다. 따라서 원래 사건의 정확한 실패 URL·발생 서버·응답 헤더·CORS/CSP 원인을 확정하지 않는다.

이번 환경의 HTTP 진단은 아래 3개 URL에 각각 GET 1회만 수행했다. 타일 다운로드나 재시도 작업은 없다. 자세한 시간·헤더는 `test-results/map-origin-http-diagnostics.json`에 보존했다. **아래는 터미널 HTTP 클라이언트 관찰이며 브라우저 네트워크 헤더를 캡처한 결과가 아니다.**

| URL | 상태 | 확인한 응답 |
|---|---:|---|
| `https://pincon.app/bloodflow/` | 404 | GitHub Pages 응답, `x-github-request-id`, `x-proxy-cache: MISS` |
| `https://tile.openstreetmap.org/8/218/99.png` | 200 | PNG, `Access-Control-Allow-Origin: *`, `Cache-Control: max-age=94034, stale-while-revalidate=604800, stale-if-error=604800`, ETag |
| `https://router.project-osrm.org/route/v1/driving/126.6847,37.4486;126.6700,37.4602?overview=false` | 200 | JSON, `code: Ok`, `Access-Control-Allow-Origin: *` |

응답의 `server: envoy`는 이 실행 환경의 네트워크 경로에 프록시가 있음을 시사하지만, 이 사실만으로 원래 503이 프록시에서 발생했다고 결론 내릴 수 없다. 404 응답의 제한적인 CSP도 GitHub 404 문서의 CSP이며, 배포되지 않은 앱의 정상 문서 CSP로 일반화하지 않는다.

루트 작업자의 별도 CUA 관찰에서는 기준 앱의 온라인 배경 버튼을 누른 뒤 현재 화면 타일 10개가 `complete=true`, `naturalWidth=256`으로 로드됐다. 예시 URL: `https://tile.openstreetmap.org/13/6978/3175.png`. 지도 `tileerror`는 관찰되지 않았다. 브라우저 도구가 네트워크 응답 헤더 API와 `performance`를 제공하지 않아 실제 브라우저 요청 헤더·각 응답 상태를 완전 수집하지는 못했다. **사용자 503은 이번 환경에서 재현되지 않았다.** 이후 강제 503 fixture 결과는 장애 복구 검증이며 원래 사건 재현과 구분해야 한다.

## 제공자 정책 확인

### OSM 표준 래스터

OSMF 공식 정책은 가용성을 보장하지 않는다. HTTPS 정규 URL·가시적인 저작권 표시·웹 Referer를 유지하고, 브라우저 기본 HTTP 캐시와 서버 Cache-Control/Expires/ETag를 존중해야 한다. 기본 `no-cache`나 캐시 우회는 금지된다. 공개 서버에서 대량 선취·전국 타일 묶음·오프라인 다운로드 기능은 허용되지 않는다. 오프라인 지도는 자체 벡터 데이터나 명시적으로 허용된 제공자를 사용한다. 소스의 자동 순환으로 접근 제한을 회피하지 않는다.

출처: <https://operations.osmfoundation.org/policies/tiles/> (2026-10-22 확인).

### OSRM 공개 데모

OSRM/FOSSGIS 공식 안내는 합리적인 비상업 사용, 초당 최대 1회, 대량·고부하 사용 금지와 무보장 가용성을 명시한다. 전국 100개 거점의 모든 쌍에 런타임 API를 호출하지 않는다. 기존 실제 경로 캐시는 보존하며, 추가 실제 도로 경로는 자체 라우터 등 적절한 환경에서 사전 생성한다. 도로가 없는 구간은 추정으로 표시한다.

출처: <https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server>, <https://routing.openstreetmap.de/about.html> (2026-10-22 확인).

### 검토한 선택지: OpenFreeMap

공식 안내상 공개 벡터 인스턴스는 API 키 없이 사용할 수 있고 출처 표시가 필요하다. Leaflet에서 쓰려면 MapLibre 어댑터 등 별도 렌더러가 필요하다. 오프라인 요청은 다운로드당 3,000타일 또는 50MB 이하·동시 4회 이하·식별 User-Agent라는 조건이 있고 SLA는 없다. 이 조사는 자동 대체 제공자 등록이나 무제한 사용 승인이 아니다. 현재 개선 범위에서 렌더러 변경 부담이 크면 실제 경계·도로를 포함한 동봉 벡터 지도를 안정적인 기본값으로 사용한다.

출처: <https://openfreemap.org/>, <https://openfreemap.org/quick_start/> (2026-10-22 확인).

## 구현에 권고한 장애 처리

1. 시뮬레이션 시계·협업 세계와 지도 생명주기를 분리한다. 지도 실패가 재고·차량·COMPUTE를 중단하지 않는다.
2. 동일 URL 진행 중 요청을 합치고 현재 뷰포트 요청만 제한된 동시성으로 처리한다. 타일마다 최대 재시도 횟수를 정하고 지수 백오프를 사용한다. 429·접근 거부는 반복하거나 출처를 바꿔 우회하지 않는다.
3. 연속 오류 시 제공자 단위 회로를 열어 새 요청을 중단하고, 내장 경계·도로·거점·저장 경로를 즉시 유지한다. 오프라인 이벤트에서 요청을 취소한다.
4. 온라인 정상/로딩/재시도/오프라인/차단/정지 상태와 완료·실패·재시도 건수를 사용자에게 표시한다. 상태 파일이나 진단 출력에 요청 URL·상태·오류 시각을 남긴다.
5. 서비스워커는 동봉 앱·벡터 데이터만 관리한다. OSM 공개 래스터를 별도 오프라인 저장소에 복제하지 않는다. 같은 출처의 서버 503도 네트워크 예외와 마찬가지로 캐시 성공 응답으로 폴백하고, 캐시가 없으면 합성 오류를 명시한다.
6. file://에서는 온라인 비활성 이유를 항상 보이게 하고, 기본 오프라인 지도에서도 실제 지형·지역 경계를 제공한다. HTTP/HTTPS에서 온라인 선택 기능을 추가한다.

제한된 재시도·인위적인 503·오프라인 시험은 복구 기능의 검증이지 공개 지도 제공자의 서비스 복구 증명은 아니다. 원래 사용자 사건의 원인 확정에는 해당 기기의 실패 요청 URL·시각·응답·콘솔 기록이 추가로 필요하다.
