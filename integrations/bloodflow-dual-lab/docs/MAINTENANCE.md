## 기기 저장소 무응답과 복원 실패의 덮어쓰기 방지 · 2026-10-23 KST

main `9093bac`의 성공한 Pages 배포, 운영 다섯 진입 경로·client 모듈·경로 자료 HTTP200을 확인했다. 협업 health는404이며 serverOrigin은 비어 있다. 운영 저장본의 실제 손상이나503을 관찰했다는 뜻은 아니다. 기존 검토 코드에 저장소 무응답을 주입하면 초기화 잠금이 풀리지 않았다. 손상된 저장본의 복원을 실패시킨 뒤에는 자동 저장이 두 번 실행돼 이전 자료를 새 초기 상태로 덮는 것을 Node에서 재현했다.

저장소 열기와 읽기/쓰기 트랜잭션에 각각5초 제한을 적용했다. 이는 전체 시작 시간이5초라는 뜻이 아니다. 늦은 열기 연결은 닫고, 실패·지연 트랜잭션은 중단한다. 연결을 공유하고 versionchange 시 닫으며, 기존 DB 이름·버전·저장 키의 호환성을 유지한다. 세계·공급망 범위·연구 메모를 검증한 뒤 한 번에 복원하고, 읽기나 복원이 실패하면 자동 저장을 허용하지 않는다.

복원 실패 뒤에도 임시 단독 연구와 JSON 내보내기는 가능하다. 화면에 지속 경고·‘파일 저장 필요’를 표시하며, 연결 창도 임시 상태임을 안내한다. ‘저장소 다시 확인’은 사용자가 명시적으로 현재 페이지를 새로 열어 확인하는 기능이다. 먼저 임시 연구를 파일로 저장하라는 안내를 제공하며, 저장 자료·캐시를 삭제하지 않는다. 자동 재시도·자동 초기화는 하지 않는다.
