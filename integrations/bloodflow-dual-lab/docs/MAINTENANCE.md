## 기기 저장소 무응답과 복원 실패의 덮어쓰기 방지 · 2026-10-23 KST

main `9093bac`의 성공한 Pages 배포, 운영 다섯 진입 경로·client 모듈·경로 자료 HTTP200을 확인했다. 협업 health는404이며 serverOrigin은 비어 있다. 운영 저장본의 실제 손상이나503을 관찰했다는 뜻은 아니다. 기존 검토 코드에 저장소 무응답을 주입하면 초기화 잠금이 풀리지 않았다. 손상된 저장본의 복원을 실패시킨 뒤에는 자동 저장이 두 번 실행돼 이전 자료를 새 초기 상태로 덮는 것을 Node에서 재현했다.

저장소 열기와 읽기/쓰기 트랜잭션에 각각5초 제한을 적용했다. 이는 전체 시작 시간이5초라는 뜻이 아니다. 늦은 열기 연결은 닫고, 실패·지연 트랜잭션은 중단한다. 연결을 공유하고 versionchange 시 닫으며, 기존 DB 이름·버전·저장 키의 호환성을 유지한다. 세계·공급망 범위·연구 메모를 검증한 뒤 한 번에 복원하고, 읽기나 복원이 실패하면 자동 저장을 허용하지 않는다.

복원 실패 뒤에도 임시 단독 연구와 JSON 내보내기는 가능하다. 화면에 지속 경고·‘파일 저장 필요’를 표시하며, 연결 창도 임시 상태임을 안내한다. ‘저장소 다시 확인’은 사용자가 명시적으로 현재 페이지를 새로 열어 확인하는 기능이다. 먼저 임시 연구를 파일로 저장하라는 안내를 제공하며, 저장 자료·캐시를 삭제하지 않는다. 자동 재시도·자동 초기화는 하지 않는다.

자동 저장은 동시에 한 번만 실행하고 후속 변경을 모아 최신 상태를 다시 저장한다. 엔진 스냅샷에는 변경 가능한 참조가 있으므로 DB를 기다리기 전에 복사한다. 스냅샷·메모·결과와 최신 위치 표시는 한 트랜잭션으로 저장하며, 완료 이벤트 뒤에만 ‘저장됨’을 표시한다. 쓰기 실패 시 자동 저장을 멈추고 파일 보관을 안내한다.

추가11개를 포함한 앱70/70·선택 PinCon58/58과 빌드를 통과했다. 열기/읽기/쓰기 지연, 늦은 콜백, 차단된 업그레이드, 복원 우선순위, 손상·잘못된 범위·메모 형식, 실패 시 저장본의 정확한 JSON 보존, 원자적 저장, 실패 후 저장 완료 표시 없음, 대기 중 변경의 최신 저장과 재고 검증을 확인한다. 할당량 오류·업그레이드 차단은 모의 트랜잭션을 이용했으며 실제 기기 저장 용량을 고갈시킨 시험은 아니다.

브라우저에서는 운영 DB와 분리한 시험 DB에 실제 IndexedDB를 사용했다. 손상된24시간 기록은 임시6시간 진행·JSON 다운로드 뒤 전체 JSON의 비암호학적 FNV-1a64 지문이 같았고 메모도 유지됐다. 정상24시간 기록은 복원 뒤30시간으로 커밋되고 재고 검증을 통과했다. 무응답 open 요청 주입 시 시간 제한 안내·조작 잠금 해제·임시6시간 계산을 확인했다. 정상화 후 다시 열면30시간이 복원됐다. 직접 키보드로 입력·확정한 메모와30시간 기록은 내장 Biology 단일 HTML에서도 복원돼36시간까지 계산·저장됐고 제제 카드3개가 표시됐다. 다른 시험 탭에서 정상 기록을 명시적으로 준비한 뒤 실제 ‘저장소 다시 확인’ 버튼으로24시간 복원과 경고 해제를 확인했다. 새 탭의 최신 인천24시간 기록 복원, 전국100거점의6시간 자동 저장·새로고침 복원, 인천으로 돌아온 뒤24시간 기록 유지도 확인했다.

앱 스크립트 콘솔 오류는 관찰되지 않았다. 초기 시험 도우미의 HTTP WebCrypto 미지원 오류는 도우미의 지문 계산을 바꿔 해결했으며 제품 오류와 구분했다. 단일 HTML은 HTTP로 열었고 실제 file://·인터넷 차단·Galaxy Tab·장시간 성능을 검증한 것은 아니다. 로컬 루프백의 HTTP 일괄 검사는 관리형 미리보기의 별도 네임스페이스에 접근할 수 없어 미검증으로 남겼다. 대신15개 배포 모듈의 소스 일치·정적 import21개/상대 모듈 참조22개·다섯 HTML의 base 기반 경로·캐시32개 경로의 파일 존재와 브라우저 초기화를 확인했다. 원본·엔진·생물학·지리 자료·다른 PinCon 경로는 변경하지 않았다. 상세 근거는 `test-results/maintenance-storage-qa.json`에 있다.

## 다음 우선순위

1. 승인된 HTTPS 협업 호스트·영속 디스크를 정하고 실제 두 태블릿에서 검증한다. 호스트를 임의 생성하거나 유료 계약하지 않는다.
2. 실제 기기에서 IndexedDB 차단·용량 부족·수동 파일 복원과 공통 서버 재접속을 검증한다. 교육용 결과 객체의 복원 형식도 근거 있는 실패 사례가 생기면 보완한다.
3. 큰 상태의 자동 저장·복원과 반복 계산을 실제 기기에서 측정한 뒤, 확인된 병목만 개선한다.

자동 개선은 최신 main과 열린 BLOODFLOW 검토 PR을 확인하고 근거 있는 변경을 선택해 테스트·빌드·검토 PR까지 수행한다. 근거 없는 변경·임의 생물학 공식·결과 조작을 하지 않는다. 운영 병합/배포·도메인·다른 PinCon 경로는 별도 승인 범위다.
