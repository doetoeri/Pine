# BLOODFLOW 유지보수 · 2026-10-22

## 실제 장애 경계와 첫 수정

PR130의 병합과 GitHub Pages 배포가 성공했고 배포된 전국 관제에서 +6시간 계산을 확인했다. 그러나 /bloodflow/api/health는 HTTP404이며 공개 runtime-config의 serverOrigin은 비어 있다. 정적 Pages 배포만으로 공통 Node/WebSocket 서버가 생기지 않는다. 실제 공동 연구용 호스트·영속 디스크 연결은 미완료다.

이전 연결 창은 서버가 없어도 만들기/코드 접속을 제시했다. 생성 실패 문구는 창 밖의 일시 알림에만 나타났고 코드 접속은 사용할 수 없는 공유 모드로 바꿀 수 있었다. 또한 이미 단독 연구 중인 기기에서 단독 전환 버튼을 누르면 불필요하게 새 세계를 만들었다.

공통 서버 상태를 먼저 확인하고, 5초 제한·동시 요청 공유·15초 캐시·명시적 다시 확인을 적용했다. HTTP성공만으로 동기화 가능하다고 판단하지 않고 BLOODFLOW 앱 표식·버전·WebSocket 지원을 확인한다. 단일 파일/잘못된 주소/HTTPS에서 HTTP로의 연결은 요청 전 거부한다. 확인 전이나 실패 시 공유 버튼을 잠그고 이유를 창 안에 유지한다. client의 guarded join은 서버 확인 실패 시 단독 세계와 실행 권한을 유지한다. 단독 연구 계속 버튼은 기존 재고·시간을 초기화하지 않는다.

새 자동 테스트 6개를 포함해 앱40/40, 현재 선택 PinCon 회귀58/58을 통과했다. 실행 명령과 상세 증거는 maintenance-tests.txt, maintenance-pincon-tests.txt, maintenance-connection-qa.json에 있다. 정적 브라우저에서는404 안내·공유 버튼 비활성·6시간→12시간 이어하기를 확인했다. 정상 Node서버에서도 상태 확인 성공·버튼 활성·실험실 생성·공유 상태 수신을 확인했다. 한 번의 일시 연결 끊김과 자동 재연결/조작 잠금 해제도 관찰했다. 실제 두 태블릿이나 장기 벽시계 운전을 검증했다는 뜻은 아니다.

## 다음 우선순위

1. 승인된 HTTPS 협업 호스트·영속 디스크를 정하고 실제 두 태블릿에서 검증한다. 호스트를 임의 생성하거나 유료 계약하지 않는다.
2. 초기 자료/모듈 로딩 실패를 네트워크 상태·파일명별로 관측하고 저장 지도로 복구할 수 있는 범위를 넓힌다.
3. 큰 상태의 자동 저장·복원과 반복 계산을 실제 기기에서 측정한 뒤, 확인된 병목만 개선한다.

자동 개선은 최신 main과 열린 BLOODFLOW 검토 PR을 확인하고 근거 있는 변경을 선택해 테스트·빌드·검토 PR까지 수행한다. 근거 없는 변경·임의 생물학 공식·결과 조작을 하지 않는다. 운영 병합/배포·도메인·다른 PinCon 경로는 별도 승인 범위다.
