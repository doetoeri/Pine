# BLOODFLOW Dual Lab 2.0 · Nationwide

혈액 부족과 혈액제제 폐기의 관계를 두 연구자가 함께 탐구하는 **교육용 웹 애플리케이션**입니다. 실제 기관 위치와 저장된 도로를 쓰지만, 재고·수요·검사·차량·온도는 가상입니다. 실제 의료 판단이나 의료기관 운영에 사용할 수 없습니다.

## 혼자 바로 열기

`dist/BLOODFLOW_Dual_Lab_Offline.html`을 내려받아 Chrome에서 여세요. 전국 경계·인천 도로·네 화면·반복 계산이 한 파일에 포함됩니다. 인터넷과 설치가 필요 없는 단독 연구 모드입니다. 기기의 다운로드 미리보기가 JavaScript를 차단하면 Chrome으로 열어야 합니다. 실제 Galaxy의 파일 열기 동작은 이번 환경에서 검증하지 않았습니다.

## 두 태블릿을 연결하기

1. PC에 Node.js 22 이상을 설치하고 ZIP 전체를 같은 폴더에 풉니다.
2. Windows는 `START_BLOODFLOW.bat`, macOS/Linux는 `sh START_BLOODFLOW.sh`를 실행합니다. 의존 라이브러리가 동봉돼 있어 `npm install`은 필요 없습니다.
3. PC와 태블릿 두 대를 같은 Wi-Fi에 연결합니다. PC 콘솔의 LAN 주소 또는 PC의 IPv4 주소를 사용해 `http://PC의IP:8787/bloodflow/nationwide`와 `/bloodflow/biology`를 엽니다. PC 자체 주소인 `localhost`를 태블릿에 입력하면 안 됩니다.
4. 전국 관제에서 `공통 세계: 전국·100거점`인지 확인하세요. 첫 기기에서 **실험실 연결 → 새 공통 실험실 만들기**를 누릅니다. 다른 기기는 생명과학 역할을 선택하고 같은 6자리 코드를 입력합니다.
5. 두 화면의 시간과 재고는 PC 서버의 상태를 따릅니다. 어느 기기든 연결을 끊으면 공통 세계를 정지합니다. 복구 후 시작 버튼을 눌러 재개합니다.

공유 네트워크가 기기 간 통신을 차단하거나 PC의 방화벽이 TCP 8787을 막으면 연결되지 않습니다. 외부 인터넷이 없는 같은 LAN에서도 PC 서버가 실행 중이면 협업할 수 있습니다. PC 종료·절전 중에는 서버도 동작하지 않습니다.

코드·역할·토큰 문제로 접속이 거절되면 자동 반복을 멈추고 화면에 이유를 유지합니다. **실험실 연결 확인**에서 코드와 역할을 확인한 뒤 다시 접속하세요. 일시적인 끊김이나 첫 상태 응답의10초 지연은 조작을 잠근 채 간격을 늘려 재접속합니다. 서버의 최신 상태를 받아야 조작이 다시 열리며 임의로 단독 시뮬레이션을 진행하지 않습니다. 서버에 해당 실험실 저장본이 없다면 호스트의 원본 자료 복구가 필요합니다.

역할 접속 정보를 읽지 못하면 새 접속을 시작하지 않고 현재 연구·연결을 유지합니다. 서버에서 받은 접속 정보를 기기에 저장하지 못한 경우에는 현재 탭에서 연결을 유지하며 지속 안내를 표시합니다. 새로 열기 전 연구 JSON과 실험실 코드를 보관하세요. 사이트 저장 권한을 확인한 뒤 같은 코드·역할로 다시 접속하면 정보 저장을 다시 확인합니다. 같은 탭에서 받은 다른 역할의 정보를 임의로 대신 사용하거나 거절된 접속 정보를 지우지 않습니다.

## 연구 순서

- **Nationwide**: `/bloodflow/nationwide`의 독립 전체 페이지입니다. 17개 고정 연구권역 지도에서 권역을 선택하면 같은 세계의 지역 상세 관제로 이동합니다. 새96거점은 가상이며 기존 인천4기관은 보존했습니다. 정책A(권역 내부)·B(인접 재배치)·C(전국 통합)를 적용하거나 Research에서 세 정책을 같은 시드로 비교합니다.
- **Engineering**: 지도를 확대·이동하고 기관·차량을 살펴봅니다. 안전재고, FIFO/FEFO, 수요 변동성, 보충 주기, 지연 배율, 재배치를 설정합니다. `새 세계 시작`은 공통 시간·재고·통계를 초기화합니다.
- **Biology**: 제제를 선택하고 ABO/RhD 모형, 보존 기준, 검사·보류·운송 상태, 가상 온도 이력을 봅니다. 제제 종류, 동일형 제한, 가상 잔여기한, 이탈·교반 조건을 독립적으로 설정할 수 있습니다. 보류 해제·제외는 근거를 기록하는 가상 연구 조작입니다.
- **Research**: N(전국 3정책), A(안전재고), B(수요 불확실성), C(제제·잔여기한·적합성) 중 실험을 정하고 기준군·실험군, 기간·반복·시드를 지정합니다. 공통 관제 세계를 바꾸지 않는 계산 복제본으로 비교합니다. 반복 계산은 쌍 사이에서 일시정지·재개하거나 중단할 수 있습니다.
- 두 역할은 해석 칸을 각각 작성하고 연구 질문·가정·한계·개선 방안을 함께 기록합니다. 보고서 본문을 자동 작성하지 않습니다.

단독 반복 계산이 시작되지 않거나 도중에 실패하면 Research에 이유를 표시하고, 이전 결과·관제 세계·두 해석을 유지합니다. 조건과 연결을 확인한 뒤 계산 버튼으로 직접 다시 시작하세요. 계산 중 공통 실험실에 접속하려면 먼저 **계산 중단**을 누르세요. 진행 중인 계산을 숨긴 채 협업으로 전환하지 않습니다. 오류 안내는 현재 탭의 표시이며 저장된 오류 이력은 아닙니다.

## 저장과 출력

상단 `•••`에서 상태 JSON, 현재 재고 CSV, 이벤트 로그를 내려받습니다. Research에서는 반복별 결과 CSV, 통계 CSV, 그래프 SVG, 조건·직접 작성한 기록·근거를 묶은 연구 JSON을 내보냅니다. 전국 Biology의 상세 목록은 권역·제제별 최대40개 표본(보류·만료 임박 우선)이고, 전체 수량은 따로 표시합니다. 재고 CSV는 표본이 아닌 전체 활성 재고를 내보냅니다. 이전 실험 결과는 저장 당시 조건과 현재 세계의 차이를 표시합니다. 실행된 실험의 조건은 결과 JSON의 `plan`과 `config`에 보존됩니다. 선택한 공급망 범위는 URL에 유지합니다. 같은 브라우저의 여러 단독 탭도 각각 자동 저장합니다. 새 실험을 시작하기 전에 상태 파일을 저장해 두면 이전 세계도 복원할 수 있습니다.

단독 모드는 탭·공급망 범위별로 IndexedDB에 10초마다, 공통 서버는 명령 처리 직후와 15초마다 자동 저장합니다. 재시작하면 일시정지로 복원합니다. 서버 실행 식별자가 바뀌면 브라우저가 마지막 저장 버전을 받아 복구하고 대기 조작을 취소합니다. 강제 종료 시 마지막 자동 저장 이후의 시간 진행은 되돌아갈 수 있습니다. 저장 권한·용량 오류가 표시되면 상태 파일을 직접 저장하세요. 서버의 `data/` 폴더는 실험실 토큰과 상태를 포함하며 공개 정적 파일로 배포하지 않습니다. 실행 중인 반복 계산 작업 자체는 재시작 후 이어지지 않으므로 같은 시드로 다시 실행합니다. 공통 서버의 파일 복원은 해당 역할의 해석과 공통 항목만 바꾸고, 다른 역할의 설정을 임의로 바꿀 수 없습니다.

상태 파일 복원은 시간·연구 기록·비교 결과를 함께 확인한 뒤 적용합니다. 결과가 없는 파일을 읽으면 이전 비교 결과는 비우며, 빠진 메모 항목은 유지합니다. 형식·분모·반복 시드·저장 통계가 맞지 않는 파일은 현재 연구를 바꾸지 않고 거절합니다. 공유 모드에서는 상대 연구자의 해석을 보존합니다. 기기 자동 저장을 읽지 못할 때는 기존 자료를 덮지 않도록 자동 저장을 멈추므로, 화면의 JSON 저장 버튼으로 임시 연구를 보관한 뒤 다시 확인하세요. 파일 검사는 외부 자료의 진위나 실제 의료 정확도를 보장하지 않습니다.

단일 HTML 두 개를 각각 여는 것은 공유 세계가 아닙니다. 오프라인 HTML은 공통 서버에 자동 연결하지 않습니다.

## 발표

Research의 `3분 발표 체험`에서 정책을 선택합니다. 전국 모드는 가상24–72시간에 서울·경기·인천 연구권역 수요가3배가 되며 A/B/C를 실제 계산해 비교합니다. 인천 모드는 안전재고 정책을 선택합니다. 시드 20261021, 가상 24–72시간에 첫 병원의 수요를 3배로 만드는 시나리오입니다. 24×로 약 3분 동안 관찰하고, 같은 초기 조건에서 안전재고 1일·6일을 실제 계산해 비교합니다. 현재 선택된 생명과학 조건을 사용합니다. `지금 정책 결과 비교`로 기다리지 않고 전체 3일 결과를 계산할 수도 있습니다. 공유 모드는 산업공학 역할에서 시작합니다.

자세한 출처·원본 보존·모형 정의·검증 범위는 `docs/`를, 실제 실행 결과는 `test-results/`를 확인하세요. `examples/`에는 기존 A/B/C 예제와 N(전국) 14일×6반복×3정책의 계산 결과가 있습니다.

**pincon.app 실서비스에는 배포하지 않았습니다.** 이 ZIP은 `/bloodflow` 아래에서만 작동하는 Node 서버와 정적 빌드를 포함합니다. PinCon의 실제 저장소 doetoeri/Pine과 GitHub Pages 구성을 확인했습니다. 운영 적용은 승인 전이며 온라인 협업 서버의 호스팅·영속 저장소 연결이 남아 있습니다. 상세 절차는 `docs/DEPLOYMENT_NATIONWIDE.md`를 참고하세요.

## 지도 장애 안내

기본 배경은 실제 지리 형태의 저장된 전국 경계와 인천 도로입니다. 온라인 배경을 켜면 현재 화면의 OSM 타일만 요청하고 기본 HTTP 캐시를 따릅니다. 동시4개·분당32회·회당 최대2번의 지수 백오프 재시도, 연속 오류 시 회로 차단과 저장 지도 복귀를 사용합니다. 403·429는 재시도·다른 제공자 우회 없이 중단합니다. `file://`는 유효한 웹 Referer가 없으므로 저장 지도를 사용합니다.

지도 카드 아래 `지도 연결 기록과 출처`에서 실제 요청 URL·HTTP 상태·브라우저가 읽을 수 있는 응답 헤더·재시도 수를 확인하고 JSON을 저장할 수 있습니다. 원래 사용자가 본503은 해당 네트워크 기록이 없어 원인을 단정할 수 없었습니다. 이번 브라우저의 실제 OSM 요청은200, 합성503은 별도로 검증했습니다. 상세는 `docs/MAP_SOURCE_AUDIT.md`와 최종 검증 보고서를 확인하세요.

## 전국 자료의 해석 범위

전국 경계는 geoBoundaries/Natural Earth의 **2021년17개 고정 연구권역**입니다. 최신 법정 행정구역을 뜻하지 않습니다. 전국 신규96거점·수급량·운송 점선은 가상입니다. 실제 도로 경로가 저장된 구간은 인천4기관 사이12개 방향뿐입니다. 나머지 추정 연결선과 제주 추가시간은 실도로·실시간 교통·실제 운항 자료가 아닙니다. 문헌 기반 보존조건과 교육용 가정은 각 화면에서 구분합니다.

`Dockerfile`은 단일 Node 서버와 영속 디스크용 추가 배포 구성입니다. Docker 자체 실행은 이 환경에서 검증하지 않았습니다. 기존 GitHub Pages의 정적 화면과 온라인 협업 서버 호스팅은 별개입니다. 운영 서버를 정한 뒤 `public/runtime-config.js`의 serverOrigin과 서버 BLOODFLOW_ALLOWED_ORIGINS를 설정해야 합니다. 배포 승인을 받기 전에는 PinCon 운영 파일·DNS·서비스워커·기존 경로를 변경하지 않습니다.
