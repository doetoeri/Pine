# 6~8분 시연 순서

1. **시작 전**: PC 크롬/엣지에서 사이트를 열고 자료 로딩을 기다린다. 기본값 복원, A, 2026년, 전역을 선택한다. F로 전체화면. 마우스를 멈추면 6.5초 뒤 부가 패널이 줄어든다.
2. **자료와 한계 (약 1분)**: 데이터·모델 패널. CBS 실제 인구와 AHN 실제 표본, KNMI 기준기간을 보여준다. “제방 성능·폭풍·경제 계수는 가정이고, 수치는 공식 침수 예보가 아니다”라고 설명한다.
3. **저지대 ≠ 홍수 (1분)**: 레이어 01 지형상 저지대와 02 잠재 노출을 전환한다. NAP보다 낮은 곳이 있어도 기존 방재 때문에 모두 침수되지는 않는다고 설명한다.
4. **모델 이벤트 자동 정지 (1분)**: A 2026, 8×, 재생. 기본 시드에서는 2029년 사건이 모델 임계값으로 발생해 자동 정지한다. 다른 입력이면 사건 연도도 달라진다. “계속 진행”은 같은 연도 다음 사건, “이 연도 건너뛰기”는 나머지 큐를 넘긴다. 제목·지역·사건 수위와 가정 표시를 읽는다.
5. **공사는 즉시 효과가 없다 (1분)**: B에 Rotterdam 제방, 착수 2030년 추가. 준공은 2040년이다. 2029년 사건을 막을 수 없음을 보여준다. 기본 B에 이미 같은 정책이 있으므로 새 발표 전 B를 비우고 한 정책으로 시작하면 설명이 쉽다. A/B 분할 비교에서 2043년 사건을 검토한다.
6. **알고리즘의 선택 (1분)**: C와 연도별 통계. OR-Tools 216개 후보, 3개 폭풍 시드, 총 €40B/연간 €3B. OPTIMAL은 제한된 선형 대리모형 결과이며 전체 국가 최적화가 아니라고 설명한다. 선택한 24개 정책과 공사기간 중의 2029년 피해를 확인한다.
7. **이주를 설계한다면 (1분)**: Apeldoorn에 2026년 시작 신도시(2038년 완공)를 먼저 만들고, Rotterdam에 2033년 시작 이주(2039년 완료)를 추가한다. 도착지를 Apeldoorn으로 지정한다. 총인구 보존과 신규 수용력, 출발·도착 인구 변화는 결과 JSON에서 확인할 수 있다.
8. **결론 (30초)**: 같은 기후 입력에서도 정책 위치와 완공 시점이 결과를 바꾼다. 정밀도를 높이려면 실제 제방·수문 운영, 해수면 NAP 연결, 고해상도 주거 분포, 실제 전기계통·교통망 자료가 추가로 필요하다.

Space: 재생/정지 · ←/→: 1년 · Shift+←/→: 이전/다음 사건 · 1/2/3: A/B/C · F: 전체화면 · Esc: 패널 닫기.

네트워크가 제한되어도 번들 실제 GIS는 표시된다. WebGL이 꺼져 있으면 실제 GIS 2D 대체 지도가 표시되며 3D만 사용할 수 없다. 자료 로딩 자체가 실패하면 오류 화면의 다시 시도를 사용한다.
